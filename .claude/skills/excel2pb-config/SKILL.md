# excel2pb 配置表设计与填写

excel2pb 会把 `assets/xls/` 下的 Excel 工作簿导出成 protobuf 二进制 + 读取代码。表格必须遵守一套约定，导出时才能通过校验。本 skill 帮你**设计表结构、填写数据、并在导出前把错误挡下来**。

关键理念：**批注（cell comment）就是字段的约束声明**（类似 ORM 的 tag）。把 `fk`、`index` 等约束写进批注，就能让工具在导出时自动校验数据有效性——外键指向不存在的行、主键重复、类型对不上，都会在导出阶段暴露。你的目标是在**动手填数据时就按规则来**，并能**在跑导出前用本 skill 的校验清单预检**，让策划少踩坑。

## 何时读哪一部分

- 设计新表 / 加字段 → 读下面「表结构」「字段类型」「批注 Tag」。
- 填多语言文本 → 读「i18n 用法」。
- 填数组 / 嵌套结构数据 → 读「数据值编码」。
- 交付前检查 → 走一遍「导出前校验清单」。
- 用代码读写 .xlsx 和批注 → 读 `references/openpyxl.md`（批注是本工具的核心，必须用能写批注的库，如 openpyxl）。

## 表结构

### 工作簿与 Sheet 命名

- **工作簿文件名 = 导出的 message / proto 名**（例：`物品.xlsx`→ 里面的 sheet 名才是 message 名，见下）。放在 `assets/xls/` 下，支持一层子文件夹分类。
- 一个工作簿可含多个 sheet。**sheet 名就是导出的 message 名**，必须是合法标识符（字母开头，字母/数字/下划线），首字母通常大写，如 `Item`、`Shop`。
- `#` 开头的 sheet：辅助计算 / 备注，**不导出**。放中间量、注释就用它。
- `~` 开头的文件：Excel 临时文件，自动跳过。
- 名为 `<枚举名>_Enum` 的 sheet：当作**枚举表**导出（下划线不能少，见「枚举表」）。

### 表头四行 + 数据

前 4 行是表头，第 5 行起是数据。逐行含义固定，**不能错位**：

| 行 | 含义 | 说明 |
| --- | --- | --- |
| 第 1 行 | 字段名 | 合法标识符。**这一行的单元格批注 = 约束 tag** |
| 第 2 行 | 字段类型 | 基础类型 + 可选修饰符，见下 |
| 第 3 行 | 导出过滤 | `c` 客户端 / `s` 服务器 / `cs` 两端都导 |
| 第 4 行 | 中文说明 | 给策划看的字段解释 |
| 第 5 行~ | 数据 | 一行一条记录 |

## 字段类型（第 2 行）

**基础类型**：`int32`、`int64`、`float`、`double`、`bool`、`string`、`timestamp`、`i18n`、枚举名、嵌套结构名。

- `timestamp`：填 `2025-03-01 08:00:05` 这种格式，导出为 int64（Unix 秒，按 config 的 `TimeZone` 换算）。格式写错会在导出时 panic。
- `i18n`：多语言文本字段，见「i18n 用法」。
- **枚举名**：填另一张 `Xxx_Enum` 表定义的枚举（如类型写 `ItemType`，对应 sheet `ItemType_Enum`）。枚举也可当主键，如 `pk AttributeType`。
- **嵌套结构名**：填另一张数据 sheet 的名字（如类型写 `Reward`），该字段就是嵌套 message。

**修饰符**（写在基础类型前，空格分隔）：

- `pk`：主键，具唯一性。例：`pk int32`。**每张数据表都必须有主键**（生成读取代码时用作 map 的 key，没有会 panic）。
- `unique`：该列值唯一。例：`unique string`。
- `repeated`：数组。例：`repeated int32`。

修饰符可组合基础类型使用，如 `pk int32`、`repeated Reward`。

### 多主键（复合主键）

一张表可以有多个 `pk` 列，语义是**复合主键：单列可以重复，但组合必须唯一**（同 SQL）。例：`区服ID + 角色ID` 两列都标 `pk`，则 `(区服, 角色)` 组合唯一即可。

> 注意：主键的第 3 行导出过滤最好写 `cs`。若某端（如客户端）过滤掉了主键列，生成该端读取代码时会找不到主键而 panic。

## 批注 Tag 机制（核心）

在**第 1 行（字段名那一行）**的单元格上加批注，就是给该字段声明约束。多个 tag 用 `;` 分隔，空白会被自动清理。工具在导出时按这些 tag 校验数据——这就是「提前检测数据有效性」的来源。

### `fk` 外键

引用其他表的字段，类似 MySQL 外键。导出时会校验：**本列每个值都必须在被引用表的那一列里存在**，否则报错（配置指向了不存在的道具/技能，就是靠它抓出来）。

**简单外键**：批注写 `fk:Item.ID`
表示本字段的值必须是 `Item` 表 `ID` 列里存在的值。支持 `repeated`：数组里每个元素都会被校验。

**嵌套结构里的外键**：批注写 `fk:Reward.ItemID=Item.ID`
表示嵌套结构 `Reward` 的 `ItemID` 子字段引用 `Item.ID`。

### `index`

`index` 表示该字段建索引（预留给读取代码用）。批注写 `index`，或与外键组合 `fk:Item.ID;index;`。

**批注示例**（第 1 行 `DropItemID` 单元格）：
```
fk:Item.ID;index;
```

> 用 openpyxl 读写批注的方法见 `references/openpyxl.md`。excel2pb 只读第 1 行的批注。

## i18n 用法（核心）

游戏要做多语言，就把需要翻译的文本字段（道具名、描述等）**类型写成 `i18n`**（第 2 行），而不是 `string`。

工作原理，理解它才能填对：

1. 策划在数据单元格里**直接填源文本**（通常是简体中文），例如道具名填「回城卷轴」。**不要手写 key**。
2. 导出时，工具把所有 `i18n` 字段的值收集进 `assets/xls/I18N.xlsx`（sheet 名 `I18N`），每条生成一个 **key = `表名_字段名_主键值`**（如 `Item_Name_1001`），列为 `ID / Cn / Tn / En`（编号 / 简体 / 繁体 / 英语）。已存在的 I18N.xlsx 会被合并而非覆盖。
3. **导出的二进制里存的是 key，不是文本**。运行时用 key 去多语言表查当前语言的文本。翻译（繁体、英语）由译者后续填进 I18N.xlsx 的 `Tn`/`En` 列。

由此推出几条**必须遵守的规则**：

- **i18n 字段所在的表必须有主键**（`pk`）。key 靠主键值拼出来（多主键则用 `_` 连接所有主键值）。没主键 → key 冲突 / 为空，多语言全乱。
- 主键值改了，等于换了 key，旧翻译会对不上。**主键要稳定**（用不变的数字 ID，别用会改的名字当主键）。
- 别把 `i18n` 字段自己设成主键。
- 需要翻译的才用 `i18n`；纯内部标识、枚举名之类用 `string`/枚举。

## 数据值编码

单元格里怎么填复合数据：

- **数组**（`repeated`）：元素用 `;` 分隔。例 `repeated int32` 填 `1;2;3`。
- **嵌套结构**：一个元素内部各子字段用 `|` 分隔（顺序 = 被引用 sheet 的列顺序），多个元素之间用 `;` 分隔。
  例：奖励 `repeated Reward`，Reward 表有 `ItemID, Count` 两列 → 填 `1001|2;1002|5` 表示两条奖励。
- 空格会被 trim；空元素会被跳过。

## 枚举表

枚举表的 sheet 名必须是 **`<枚举名>_Enum`**（下划线不能少，工具按 `_` 切分取前段作为枚举名）。例：sheet `ItemType_Enum` → 枚举名 `ItemType`，数据字段类型就写 `ItemType`。格式：

| 行 | 内容 |
| --- | --- |
| 第 1 行 | 表头（会被跳过），惯例 `Name / Value / Comment` |
| 第 2 行~ | 每行一个枚举项：第 1 列枚举名、第 2 列枚举值(整数)、第 3 列可选注释 |

**首项必须是值 0**（proto3 规定枚举第一个值为 0）。惯例是加一个 `InvalidXxx = 0` 作为默认/非法值放第一行，例如：

| Name | Value | Comment |
| --- | --- | --- |
| InvalidItemType | 0 | 非法/默认 |
| Consumable | 1 | 消耗品 |
| Weapon | 2 | 武器 |

数据表里引用枚举的字段，值可填**枚举名**（如 `Weapon`）或**枚举整数值**（如 `2`）——两者都支持。

## 导出前校验清单

交付前 / 跑 excel2pb 前，逐项检查。分两类严重度：

**硬错误（会中断导出，必须修）**
1. **主键**：每张数据表有 `pk`；(复合)主键组合在所有数据行里唯一，无重复。
2. **unique 列**：标了 `unique` 的列无重复值。
3. **类型可解析**：`int*` 列全是整数；`float/double` 是数字；`bool` 是 `true/false`；`timestamp` 严格是 `YYYY-MM-DD HH:MM:SS`。
4. **枚举值**：引用枚举的单元格，要么是合法枚举名（存在于对应 Enum 表），要么是整数。
5. **类型名有效**：第 2 行的基础类型 ∈ 支持列表，或是已定义的枚举名 / sheet 名。
6. **i18n 需主键**：含 `i18n` 字段的表必须有 `pk`。
7. **主键导出过滤**：主键第 3 行含要生成代码的目标端（一般 `cs`）。

**软错误（导出不中断，仅告警，但数据其实是错的）**
8. **外键存在性**：每个 `fk` 引用的表和列存在；本列每个值（含 `repeated` 拆分后、嵌套拆分后）都能在被引用列中找到。
9. **嵌套结构列数**：嵌套值用 `|` 拆出的子字段个数，与被引用 sheet 的列数一致。

**结构性检查**
10. 表头正好 4 行，字段名/类型/过滤/说明不错位；字段名、sheet 名是合法标识符；数据从第 5 行开始。
11. **枚举表**：sheet 名形如 `<名>_Enum`（带下划线）；**首项枚举值为 0**（proto3 要求，否则 protoc 编译失败连带导出失败），惯例首项 `InvalidXxx = 0`。

发现问题时，明确指出是哪张表、哪个字段、哪一行（换算成 Excel 行号 = 数据行下标 + 5），并说明违反了哪条规则、怎么改。

## 工作流

**设计新表时**：先定 sheet 名（=message 名）→ 铺第 1~4 行表头 → 给需要约束的字段加第 1 行批注（fk/index）→ 需要翻译的文本用 `i18n` 类型并确认表有 `pk` → 引用别的表就加 `fk` → 用「校验清单」自查结构。

**填数据时**：从第 5 行开始，一行一条 → 数组/嵌套按「数据值编码」填 → i18n 字段填源文本别填 key → 填完走一遍「校验清单」，重点查主键唯一、外键存在、类型/时间戳格式。

**读写 .xlsx**：批注是本工具核心，务必用支持读写单元格批注的库。openpyxl 的具体用法（读表头、读/写第 1 行批注、遍历数据、生成新表）见 `references/openpyxl.md`。
